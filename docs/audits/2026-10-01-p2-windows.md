## Windows

- `package.json` y el lockfile declaran `os: ["win32"]`.
- El proceso principal, el procesador y las herramientas de desarrollo, pruebas y compilación rechazan otras plataformas.
- La búsqueda de ejecutables, las fuentes, los controles de ventana, la terminación de procesos y la selección de encoders usan las rutas y capacidades de Windows.
- Ambos jobs de CI utilizan `windows-latest`; el empaquetado selecciona Windows explícitamente.
- Se mantienen las dependencias opcionales de terceros tal como aparecen en el lockfile y los informes históricos de auditoría.

## Validación

`npm run verify` terminó correctamente: lint, formato, 1.158 pruebas de JavaScript en 168 archivos y los 29 archivos de pruebas de Python. Los hashes de código y configuración se mantuvieron estables durante ese pase final.

También pasaron la compilación final del renderer, `npm run build:processor` y el empaquetado local de Windows x64 con el target `dir` y publicación desactivada. Se verificó el inicio del worker tanto desde `bin/beru-processor.exe` como desde el paquete generado, con FFmpeg/ffprobe incluidos.

Un video real con matriz de rotación de 90 grados se detectó como 90 × 160 y se recortó a 80 × 144, tanto desde Python como con el ejecutable compilado.

Los comandos locales utilizan `TEMP` y `TMP` dentro de `.audit-tmp` para evitar el fallo preexistente de permisos del directorio temporal global. Esta configuración se limita a los procesos de verificación.
