# CONTEXT — Beru domain

Beru is a batch video editor. Excel rows drive text overlays onto a queue of videos; blur, crop, delogo, and watermark are Operations on those videos. Electron main starts a Processing Run; the Python Processor consumes a Job Manifest.

## Glossary

**QueueItem** — One input video in the editor queue, with probe metadata and Operations.

**Video Transform** — Per-QueueItem `{rotation, flipH, flipV, outputHeight, outputWidth, fitMode}` edit, separate from source metadata and regional Operations. Quarter turns are clockwise; flips use the rotated frame axes. The Processor applies Operations and watermark before rotation, flips and resize. A height alone scales proportionally and never enlarges; width and height together give that exact even-pixel size, enlarging if needed, and `fitMode` fills a different aspect by stretching, padding with black bars or cropping the overflow. `outputLayout` (JS) and `output_layout` (Python) share the content rectangle through `output-geometry-cases.json`. Identity preserves stream copy when other edits permit it.

**Original Audio** — Per-QueueItem `{gain, muted}` export settings, separate from playback volume. Gain attenuates from 0 to 1; mute keeps the original track silent and preserves gain for unmute. Missing, null, blank or non-finite gain defaults to 1. A source without audio stays without audio. Jobs carry `audio_gain` and `audio_muted`; edited audio is encoded while identity video can be copied.

**External Audio** — One optional per-QueueItem asset `{path, name, duration, version, mode, offset, trimStart, trimEnd, gain}`. Main validates approved audio paths and probes the track; Jobs contain only the processing fields as `external_audio`, with snake_case trim fields. Offset is in output seconds within the trimmed, retimed cycle. Asset trim is in its own source seconds. Audio never extends the video: short tracks leave silence, long tracks are cut. Mix assigns fixed half weights to both tracks with no automatic normalization; replace uses only the asset at its gain and channel count. Without an original track the asset uses full gain. The Processor probes the real source track when composing, even if cached metadata lacks it. The inspector audition plays the original asset, not the composed export. Asset stat/version participates in media URLs and exact-preview cache invalidation.

**Video Timing** — Per-QueueItem `{rate, repeatCount}` edits, separate from Processor telemetry `QueueItem.speed`. Rate is 0.25–4, identity 1; original audio uses pitch-preserving tempo and source FPS is retained. Trim and Operation windows stay in source seconds. A cycle lasts `(min(trimEnd, sourceDuration) - trimStart) / rate`; repeatCount is the total cycles, 1–20, with a 7200-second limit for edited timing. External audio offset belongs to the retimed cycle, and repetition repeats the entire composed cycle. Jobs carry `playback_rate` and `repeat_count`. The Processor writes one cycle into the run's private scratch, then concatenates with explicit analytic durations and encodes at source FPS to avoid accumulated fractional-frame/AAC drift. One final completion belongs to the original Job. Run disposal removes scratch even after hard termination. Preview cycle selection is ephemeral: the source timeline is unchanged, direct frames use source seconds, and artifact seeks use `(sourceTime-trimStart)/rate + cycle*cycleDuration`. Edited timing outside trim renders the direct source frame; neutral legacy artifact seeks preserve endpoint clamping.

**Editing History** — Undo/redo snapshots contain Operations, Video Transform, Original Audio, External Audio and Video Timing for the selected QueueItem. They exclude progress, run state and outputs. A continuous slider gesture owns its video and history stack; undo/redo, another edit or a video selection starts a new step. Session persists these edits; Project still excludes the Queue.

Changing trim or restoring history cannot extend edited timing beyond 7200 seconds. A rejected change preserves the current QueueItem and both history stacks; neutral timing remains valid for longer sources.

**Timeline Editor Session** — The montage has a document owner that changes on open or recovery. Pending imports, relinks, proxies and saves apply only to their original owner; competing opens keep the latest request. Saves name their previously selected document path explicitly, so a late save cannot redirect another document's writes. Opening another document requires discarding unsaved changes. Unsaved montage work participates in the window-close warning, and autosave belongs to the application lifetime across workspace switches. Autosave IO is ordered; a completed save only removes an identical saved snapshot. Playback retains the final source frame while a monotonic clock completes the segment's frame-rounded duration before advancing or stopping.

Preview transport and navigation use the full project duration, including overlays beyond the last clip. That trailing interval shows the canvas background and active overlays, with a monotonic clock for playback and seeking.

Media read ownership is tracked separately for the queue, composition and montage. Releasing one consumer preserves paths retained by another; montage ownership includes undo, redo and active gesture snapshots. Replacing a document releases paths that no consumer still needs.

**Operation** — An overlay or region effect on a video (`text`, `blur`, `crop`, `delogo`, `image`). Factory, export filter, and Job wire format live in `src/utils/operation.js`. UI uses camelCase; `operationToJobPayload` emits snake_case plus pixel Regions for the Processor.

**Fechero** — Operation `datetime`: a date/time stamp that advances with the source timeline. It is drawn last, on the output frame after crops, rotation, flips and resize, so its region is normalized to that frame and Jobs send it normalized; it never deforms, rotates or mirrors. Changing the output size rescales it by the new height (shrinking to fit the width) without stretching. The live preview maps it onto the source view (`stamp-geometry.js`), so bars, crop and rotation only show in the rendered preview, which the Fechero workspace opens on its rendered frame. `clockStart` is the wall clock (no zone) of the source's first frame; Jobs carry it as `clock_start_epoch` seconds and FFmpeg formats it as UTC, so the exporting machine's zone never shifts it. Operations run before trim and retiming, so a trimmed export shows the real time of each source frame, a retimed one advances at that rate, and repetition repeats the clock. Each digit is an FFmpeg `eif` expansion so the text-spacing fallback still applies. `single` (one box) is the default; `split` layout draws date and time in separate boxes whose widths `splitClockRegion`/`split_clock_region` share by character count. Exact preview adds its `-ss` seek to the epoch, since the seek restarts filter `t` at 0. Not linked to Excel.

**Region** — Normalized `{x,y,w,h}` rectangle on a video (`src/utils/types.js`). Jobs send pixel rectangles.

**Text Overlay** — Text style and layout for preview and export. `textScaleX` stretches glyphs horizontally: layout, wrapping and fit run in a box `1/textScaleX` as wide as the inner area, then the run is stretched onto it (CSS `scaleX`, a scaled transparent layer in FFmpeg). Translucent backgrounds are RGBA layers composited with overlay, because drawbox shifts chroma when it blends in YUV. Merge, persist, and hydrate live in `src/utils/text-style.js`. Preview CSS layout is `src/utils/text-layout.js`; drawtext math is the Python adapter.

**TemplateRegion** — A batch text slot (label + Region + style) filled from Excel.

**Batch Export** — Export a queue of videos using TemplateRegions filled from Excel. Workbook rows, column mapping, video matches and linked Operations form one coherent editing state. Importing or remapping Excel explicitly applies its text; editing or restoring a Session preserves per-video Operations. Row indices and match statuses are derived from workbook rows, the ID column and video filenames. Preview may show labels for empty text slots; Jobs never export those labels.

**Job** — Snake_case payload discriminated by `kind`: `video` owns one source and its edits; `composition` owns ordered normalized video clips, canvas, FPS and output; `stabilization` owns a source, settings and optional sample length. `normalizeJob` in `shared/job-manifest.js` defines each variant and its defaults. Legacy Jobs without a kind become video Jobs; legacy video fields borrowed by a composition parent are removed, while extension fields remain. Producers and manifest adapters route through this boundary. `jobMediaSources` enumerates each variant's videos and assets so output validation never needs fabricated input Jobs. Python estimates a composition's peak sequential stage from every clip and its output canvas, not from the first clip's metadata.

**Job Manifest** — `{ type: "beru-job-manifest", version, createdAt, jobs }` validated/normalized once by `normalizeManifest` in `shared/job-manifest.js`; legacy bare arrays are still accepted at the main-process seam.

**Composition** — A separate versioned `beru-composition` document with ordered entries, each owning a stable id and a snapshot of a QueueItem's editing state. Entry trim/timing edits belong to the composition and never modify the source queue or Excel matches. Canvas, contain/cover fit and output CFR FPS are explicit; output is SDR yuv420p, square pixels and stereo 48kHz, with silence for entries without audio. Each entry is composed before canvas/audio normalization. Segment duration is rounded up to one output frame, so boundaries lie on the output grid. One composition Job and one confirmed result belong to the run; entry intermediates belong to its private scratch. Session/document persistence and results are separate from batch projects and queue indices.

Video transform, original audio, external audio and timing share `normalizeVideoSettings` across Session, history and composition snapshots. Their metadata, Operations cloning and trim ownership remain specific to each boundary. `compositionDuration` owns the output frame rounding used by validation and the dialog. Loading a composition in main restores its media paths with the existing Session permission policy and returns the parsed document and authorization results together; the renderer only applies that response while its document owner is current. Document IO and frame requests have separate lifecycle owners.

Composition documents reject malformed Operation entries before restoring state or authorizing media. A composition preview reply also belongs to the requested source timestamp: seeking while it renders discards that reply and permits another request at the current time.

**Stabilization** — A derived-media Job (`kind: "stabilization"`, id -2) that turns one QueueItem's source file into a new MP4; the original, its Operations and its Excel matches are never touched, and the result joins the queue only when the user adds it. Two Processor phases inside one run (vidstab detection into a private scratch, then transform) share its context and cancellation; the scratch is deleted with the run. Settings are an intensity (low, medium, high) and an edge policy (zoom hides borders by cropping in, keep leaves black borders). Output keeps the source presentation size, SDR yuv420p, audio copied when its codec allows. HDR is rejected. A sample runs the same job on the first seconds into a separate file. Because the result is a new file, Operation regions are placed on it afterwards, in its own coordinates.

Confirmed results carry source path and `sample`/`full` variant from the launched Job. Signatures only compare editing state; their serialization never decides the variant or queue action. A failed or cancelled attempt retains the preceding result's metadata. An older in-memory result without a variant is shown as previous and cannot be added until a complete result explicitly identifies itself as full; media results are not persisted in Session.

**Processing Run** — One execution of the Processor over a Job Manifest, identified by a run id. A run produces one terminal outcome and owns its cancellation; a cancelled run releases execution capacity after termination finishes. Job results belong to that run and are counted once, including retries. A confirmed completion retains its export artifact after cancellation or a run failure; confirmed Job errors remain visible. Pending Jobs return to idle and can be retried. A failure without a Job identity produces one run-level error notice. Events and replies from an older run cannot change a newer run.

The renderer routes each run's results to either the queue or a derived-media artifact. Artifact progress and summaries stay in `mediaExport` and leave batch counters intact. A terminal outcome clears the active run context atomically; confirmed artifacts remain available in their dialogs while the footer returns to batch progress.

Per-Job errors use the manifest identity, including negative derived-media IDs, and keep the run active until its terminal outcome. They do not terminate the renderer's run before the Processor releases execution capacity.

Run-started and run-finished events are shared even when the editor routes Job progress privately. An editor-owned run occupies the common processing state without adopting queue results or changing batch counters; its terminal event releases that state.

Terminal run results include confirmed output paths and file identities, including alternate names chosen to preserve existing files. Editor exports, frames and proxies consume those confirmed paths. Preparation cancellation invalidates pending work before a run starts; an editor owner can cancel its preparation independently, while general processing cancellation invalidates every owner.

Export preparation for video batches, composition, stabilization, editor exports, frames and proxies shares `startExportRun` in main. Kind and editor source identity validation stay in each handler; processor availability, media authorization, readable inputs, output collisions and cancellation belong to that shared flow. Each asynchronous preparation stage and the final handoff to execution check cancellation before a run exists. Batch, composition and stabilization reject existing outputs unless overwrite is explicit; editor exports, frames and proxies preserve them through the run's alternate filename publication.

An export's currency is separate from the last run's status. `hasUnexportedWork` compares the current Job against its confirmed `exportSignature`, including edits, encode profile, watermark and requested output path. The confirmed artifact is retained when editing; undo back to the exported state makes it current again. An alternative filename allocated while promoting the artifact does not change the requested Job signature. Legacy in-memory completions without a signature retain their status-based behavior.

**Processor** — Packaged Python (`processor.py` / `beru-processor.exe`) that builds the FFmpeg filter graph and encodes. Each Processing Run owns its execution settings, media tools, cancellation, progress and software fallback capacity. Scheduling settings are immutable and derived by `process_jobs` without changing the caller's runtime context; retry passes replace only the worker count and share cancellation, progress and software admission. FFmpeg owns its progress rate limit. Subsequent runs start with independent execution state.

`ClipRenderer` prepares a `VideoPlan` for copy or encode and renders intermediate media without terminal events. Composition and repetition execute their plans through `ClipRenderer.execute` without re-entering the Job dispatcher. Cancellation uses `ProcessingCancelled`, independently of an error's message. One Job executor emits completion or cancellation; the batch emits a failed Job only after its retry policy is settled. All renders within a Job share hardware failure state, and temporal, cycle and composition intermediates live in the run's scratch directory.

`ClipRenderer` receives the Job and its `BatchContext`; it owns the use of probe, filter, encode and media execution modules. Tests and performance tools substitute dependencies in their owning modules. `processor.py` coordinates execution without copying patched font/filter state between modules. Video and thread arguments belong to `encode_args.py`, with concurrency supplied explicitly.

**Exact Preview** — A rendered frame of the selected video at its current time, including applied Operations and a valid logo draft. A frame belongs to that video, time and editing state; obsolete results cannot replace it or reopen a closed preview. A previous frame may remain visible as stale while its replacement is prepared. Comparison offers live, before, after and side-by-side views in logo editing; edits return to live. Closing ends pending updates until another explicit render or, in logo editing, a change to the frame's content or time.

**Preset** — A Project document with `type: beru-preset` and no Excel. Distinct from UI `TEXT_STYLE_PRESETS`.

**Project** — Saved document (`beru-project`): templates, text style, defaults, Excel mapping, watermark. Queue is not part of the file. Validate lives in `shared/project-document.js`.

**Session** — Persistence adapter for the live Queue (and related editor fields) in sessionStorage. Not a Project file.

**Encode profile** — Named encode settings from `resources/encode-profiles.json` (`fast`, `balanced`, `quality`, `uquality`).

Worker caps and RAM estimation constants share `resources/worker-policy.json` between main and Python. The resource participates in the processor build fingerprint and PyInstaller data. Renderer capacity inputs include geometry, timing, trim, Operations, TemplateRegions and enabled watermark; the capacity signature is derived from those same inputs. Memory measurement remains specific to each runtime.
